# 功能清单（v2.2.1）

图例：✅ 完全可用 ｜ ⚠️ 有条件可用 ｜ ❌ 未实现

## 一、总览页

| 功能 | 状态 | 说明 |
|---|---|---|
| 百分比仪表盘 | ✅ | 显存、内存、GPU 3D、CPU 四项，环形显示占用百分比 |
| **CPU 取 P 核峰值** | ✅ | 有大小核的机器上取**性能核**中最高的一个，不取全局峰值。实测小核满载时全局峰值亮红 100% 而 P 核仅 24.9%，旧口径会误报 |
| **CPU 详情页** | ✅ | 点击 CPU 仪表进入：一行结论 + 四项汇总（P / E / 全局 / 总 CPU）+ 系统压力（磁盘吞吐、拓扑）+ 按大小核分组的每核条形图；「← 返回」回总览 |
| 同构机器行为不变 | ✅ | 无大小核的机器上 P 核峰值 == 全局峰值，标题仍为「CPU 单核峰值」，详情页不出现「大核 / 小核」说法 |
| 四档配色 | ✅ | 0~30% 绿、31~60% 蓝、61~80% 橙、81~100% 红；口径在 `OccupancyPalette`，有单测锁死 |
| 超范围读数钳制 | ✅ | PDH 在读数间隔异常时给过 123%，界面上不会出现越界百分比 |
| **内存优化按钮** | ✅ | 内存仪表下方「优化」按钮，释放闲置工作集；三态可见（执行中 / 成功 / 失败）；**不结束任何进程** |
| 内存优化结果如实上报 | ✅ | 成功显示「已释放 461 MB（26 个进程）」；失败写清原因（权限不足 / 接口失败 / 回读无变化） |
| **系统压力并入详情页** | ✅ | v2.1.1 起从总览页移入 CPU 详情页：磁盘吞吐 + 总 CPU 与 P/E 核峰值同页对照，避免「总 CPU」两处重复 |
| 系统压力独立降级 | ✅ | 某项计数器缺失时另一项照常工作，采不到的项在副标题列出，不显示 0 冒充读数 |
| 游戏库自动扫描 | ✅ | 同时扫描 Steam 与 WeGame，启动时自动执行，可手动「重新扫描」 |
| 平台分组统计 | ✅ | 显示「已扫描到 N 款游戏（WeGame 2 款，Steam 1 款）」 |
| 非游戏过滤 | ✅ | Wallpaper Engine、SteamVR、各类 Redistributable 不入库 |
| 显存是否充足 | ✅ | **按每款游戏自己的正常需求（1080p 高画质）对比本机实时剩余显存**，每秒重算；结论只有「显存充足 / 显存紧张」两种；悬停可看需求、剩余与占比 |
| 剩余显存口径 | ✅ | 剩余 = 显存容量 − 当前占用（PDH `GPU Adapter Memory\Total Committed`）。总容量再大，被别的程序占满时同样判「紧张」 |

> 内存优化默认保护：系统必要进程（Session 0 / 注册服务 / 系统目录）、本程序自身、
> 当前前台窗口进程、工作集小于 16MB 的进程。前台进程被清会让用户明显感到卡顿。

> **系统压力只做两项，是实测筛出来的结果**：处理器队列长度（24 核压到 79% CPU 仍为 0~2）、
> 分页文件使用率（静态 25% 而同期 `Pages/sec` 为 0）、网络吞吐（与游戏延迟无关）三项
> 实测价值不足，已筛除。**温度监控明确不做**（ACPI 只能给恒定的环境温度，真实核心温度需内核驱动）。
> 实测证据见 [已知限制](04-已知限制.md) 第十三、十四节。

## 二、外设页

| 功能 | 状态 | 说明 |
|---|---|---|
| 三类外设 | ✅ | 鼠标、键盘、耳机，按类别固定排序 |
| 具体型号 | ✅ | 优先用设备自报的 `HidD_GetProductString`，其次 BusReported 描述（实测 G610 显示为 `G610`，接收器鼠标显示为 `VXE NordicMouse 1K Dongle`） |
| 剩余电量 | ✅ | 蓝牙外设走 Windows 电量上报；**VXE/ATK（Compx）鼠标走私有 HID 协议实时读取（v1.1.0，实测 65%）**；其他厂商私有协议显示「未知」 |
| 有线 / 无线 | ✅ | 蓝牙枚举 = 无线；产品名含 Dongle/接收器 = 无线接收器；ACPI / 板载声卡 = 有线 |
| 有线设备主题色 | ✅ | 模块主题为蓝色，电量环整圈蓝，中心写「有线」 |
| 触摸板排除 | ✅ | Windows 把触摸板归到 Mouse 类，靠「父设备是 ACPI」排除，笔记本不会凭空多一只鼠标 |
| 笔记本自带键盘排除 | ✅ | 父设备挂在 ACPI 下的键盘不显示（v1.0.1）；外接 USB / 蓝牙键盘不受影响 |
| 虚拟设备排除 | ✅ | 虚拟 HID 框架（VHF）、UMDF 虚拟设备、虚拟音频端点都不计入 |
| 复合设备合并 | ✅ | 同一只鼠标的 MI_00/MI_01/MI_02 接口、接收器同时上报的键盘集合，合并为一台 |
| 手动重新扫描 | ✅ | 插拔设备后点「重新扫描」 |

> 电量读取三条路（v1.1.0）：
> 1. 蓝牙外设：Windows `DEVPKEY_Bluetooth_Battery` 直接给百分比
> 2. **VXE/ATK（Compx）鼠标：`VxeBatterySource` 走 hub.atk.pro 驱动逆向出来的私有协议**
>    （FF02 厂商集合，16 字节包，命令 GetBatteryLevel=4，报告 ID 8，校验和字节15）
> 3. 其他厂商（罗技 HID++ 等）仍显示「未知」，不猜数字。

## 三、游戏模式

| 功能 | 状态 | 说明 |
|---|---|---|
| 高性能电源计划 | ✅ | 切到高性能，退出时恢复原计划 |
| 关闭后台干扰进程 | ✅ | 只结束白名单里勾选的、且当前正在运行的应用 |
| **释放闲置内存** | ✅ | v2.0.0 起作为**可选动作**加入：失败不拦路，但会进 `Warnings` 如实上报 |
| 关闭时自动恢复进程 | ✅ | 退出游戏模式按原路径重新拉起被结束的进程（v1.0.1）；恢复失败如实上报 |
| 必要进程自动保护 | ✅ | Session 0 服务、已注册服务、Windows 组件一律不结束，也不出现在白名单里 |
| 白名单可自定义 | ✅ | 「开启游戏模式」旁的白名单设置按键展开面板：应用图标 + 中文应用名；勾选状态持久化到 `%LocalAppData%\GameOptimizer\background-whitelist.json` |
| 结束结果如实上报 | ✅ | 明确告知结束几个、释放多少 MB、哪些被系统保护 |
| 失败自动回滚 | ✅ | 任一**必需**动作失败，立即回滚已执行部分 |
| 回滚失败上报 | ✅ | 明确告知哪项没还原，绝不静默显示「已还原」 |
| **可选动作语义** | ✅ | `AddOptional()`：可选动作失败不回滚、不中断，但必须进 `Warnings` |

> 显卡性能偏好已移除：核显机器上没有可调度的独立 GPU，写 `GpuPreference` 不会生效，属于空转项。

> 内存清理的 `Revert()` 是空操作：释放工作集不是状态改动，放出去的页会随进程继续运行自然回到内存，
> 没有「恢复」这回事。它也因此在崩溃兜底快照里不占字段。

## 四、下载页（v2.2.0）

侧边栏「下载」导航项，排在「设置」**上方**。下载内核 `Core/Download/DownloadService`
不依赖任何 WPF 类型，可脱离界面单测。

| 功能 | 状态 | 说明 |
|---|---|---|
| 手动新建任务 | ✅ | 粘贴 http / https 直链，自动识别文件名（可手改），「浏览」选保存目录 |
| 多线程分片 | ✅ | 默认 4 片，1~16 可调；按 4KB 对齐，末片吃掉余数；小于 256KB 不分片 |
| 断点续传 | ✅ | 每片已收字节与片 SHA1 落盘；重启后只对「上次被硬中断」的任务自动续传，用户主动暂停的保持暂停 |
| SHA1 校验 | ✅ | 服务端给 Digest 就比对；没给就如实写「未校验（服务端未提供校验值）」，**不假装通过** |
| 校验失败重下 | ✅ | 用片哈希定位坏片、只重下坏片；定位不到（传输途中混入坏数据）才整份重下，最多 `IntegrityRetries` 轮 |
| 异常重试 | ✅ | 网络类错误指数退避（1× / 2× / 4× 基准，上限 30 秒，带 ±20% 抖动），默认重试 3 次 |
| 实时速度 / 剩余时间 | ✅ | 每秒采样、指数平滑；速度未知时显示「剩余 --」，不编造数字 |
| 全局限速 | ✅ | 令牌桶由所有任务共享，支持「10MB」「500KB」写法，改完立即生效 |
| 任务队列 | ✅ | 最大同时下载数可配（默认 2 个任务 × 每任务 4 片）；名额满时停在「排队中」 |
| 六种状态 | ✅ | 排队中 / 下载中 / 已暂停 / 已完成 / 下载失败 / 已取消；界面按「正在下载 / 下载失败 / 已完成」分组 |
| 批量操作 | ✅ | 全部暂停、全部开始、清空已完成（只删记录，不动已下好的文件） |
| 持久化 | ✅ | 写 `%LocalAppData%\GameOptimizer\downloads.json`，先写 `.tmp` 再原子改名；每 5 秒兜底保存 + 退出前落盘 |
| 打开所在文件夹 | ✅ | 文件在就选中它，不在就打开所在目录，都不在如实说明 |

> 实现参考 PCL2 下载器的**交互与能力**（MIT），为独立重写，未复制其源码；
> 只用标准 HTTP（GET + Range），不接任何第三方私有接口。版权说明见
> `src/GameOptimizer.Core/Download/Notice.cs`。

## 六、诊断归因

只保留无需额外权限的部分。帧时间采集与归因引擎已在 v1.0.0 随「数据」页一并移除。

| 功能 | 状态 | 说明 |
|---|---|---|
| 按游戏的显存判定 | ✅ | 每款游戏按 1080p 高画质的正常需求对比**本机当前剩余显存**，≥85% 判「紧张」 |
| 显存容量实测 | ✅ | DXGI `GetDesc1` 读专用/共享显存；独显取专用，核显取专用 + 共享 |
| 内存占用 | ✅ | 用标称容量作分母（15.73GB 显示为 16GB），符合用户心智 |
