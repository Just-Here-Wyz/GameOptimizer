# 版本规则

## 编号约定（用户设定）

| 变更类型 | 版本变化 | 示例 |
|---|---|---|
| **外观 / 功能性更新** | 次版本号 +1，修订号归零 | v0.5.0 → **v1.0.0** |
| **仅修 bug** | 修订号 +1 | v0.5.0 → **v0.5.1** → v0.5.2 … |
| 大版本（如 v1.x）内的外观更新 | 同上规则 | v1.0.0 → **v2.0.0** |

**版本号由用户手动设定**，不要自动递增。

## 版本号在哪里改

只需要改一个文件：

```
Directory.Build.props   ← 顶部的 <Version>
```

```xml
<Version>0.5.0</Version>
<AssemblyVersion>0.5.0.0</AssemblyVersion>
<FileVersion>0.5.0.0</FileVersion>
```

改完后重新构建，exe 的属性里就是新版本号。

## 发布流程

每次更新按这个顺序做，确保可追溯：

1. **改代码**
2. **补测试**，`dotnet test` 全绿
3. **改 `Directory.Build.props` 里的版本号**
4. **同步更新 `docs/` 下受影响的文档**（功能清单、已知限制、变更记录）
5. **提交**，提交信息用中文，格式：

```
fix: 简短说明      ← 修 bug
feat: 简短说明     ← 新功能
docs: 简短说明     ← 仅文档
refactor: 简短说明 ← 重构
```

6. **打标签**：

```powershell
git tag -a v0.5.0 -m "v0.5.0"
```

## 变更记录怎么写

在 `docs/06-变更记录.md` 顶部追加一节，至少写清楚：

- **用户能看到什么变化**（不是技术实现）
- **修了什么 bug，根因是什么**（避免以后重复踩坑）
- **测试数量变化**
