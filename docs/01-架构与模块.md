# 架构与模块

## 分层

```
GameOptimizer.sln
├── src/GameOptimizer.Core        纯逻辑，无 UI 依赖，可单测
│   ├── Collection/               数据采集（PDH 计数器、PresentMon、内存信息）
│   ├── Analysis/                 判定与归因（显存、帧时间、曲线坐标）
│   ├── Library/                  游戏库扫描与非游戏过滤
│   ├── GameMode/                 游戏模式动作与回滚总控
│   └── Models/                   共享数据模型
├── src/GameOptimizer.App         WPF 界面
│   ├── ViewModels/               MainViewModel（全部界面状态）
│   └── Views/                    MainWindow、Sparkline（自绘折线图）
├── tests/GameOptimizer.Tests     xUnit 用例
└── tools/                        运维脚本（PresentMon 授权、链路验证）
```

**关键约束**：Core 不引用任何 WPF 类型。所有能测的逻辑都在 Core 里。
唯一的例外是 `ViewModel` 里的 `System.Windows.Visibility`，属于既有技术债。

## 数据流

```
                    ┌──────────────────┐
                    │  PdhSampler      │  每秒采样一次
                    │  (WDDM 计数器)   │  显存/内存/GPU/单核
                    └────────┬─────────┘
                             │ SampleFrame
┌──────────────────┐         ▼
│ FrameTimeSource  │   ┌──────────────┐
│ (PresentMon      │──▶│ MainViewModel│──▶ Charts (Sparkline 折线)
│  stdout 流式)    │   │              │──▶ 顶部状态栏
└──────────────────┘   └──────┬───────┘
                              │ 会话结束时
                              ▼
                    ┌──────────────────┐
                    │ DiagnosisEngine  │  尖峰 × 指标联动归因
                    │ VramAssessor     │  双指标显存判定
                    └──────────────────┘
```

## 各模块职责

### Collection

| 类 | 职责 | 关键点 |
|---|---|---|
| `PdhSampler` | 读 WDDM 性能计数器 | 主适配器按 `Total Committed` 最大值选，不能用 `FirstOrDefault`（会选到虚拟显示器） |
| `FrameTimeSource` | 调 PresentMon 抓逐帧数据 | 必须用 `--output_stdout`；`--output_file` 的 CSV 采集期间被独占，外部读不到 |
| `GameProcessDetector` | 找正在运行的游戏 | 反作弊会阻止读取 exe 路径，必须有「进程名前缀匹配」退化路径 |
| `SystemMemoryInfo` | 物理内存总量 | 用 P/Invoke `GlobalMemoryStatusEx`；标称容量向上取整（15.73GB → 16GB） |
| `GpuMemoryInfo` | 显卡显存容量 | DXGI `GetDesc1`。独显取专用显存，核显取专用 + 共享；排除软件适配器 |

### Analysis

| 类 | 职责 | 关键点 |
|---|---|---|
| `VramAssessor` | 会话实测显存是否达标 | **双指标**：显存预算占用率 + 系统内存余量。核显没有独立显存，只看 Dedicated 永远是 0 |
| `GameVramDemand` | 每款游戏的显存需求 | 1080p 四档画质的需求表；未收录按体积推断并标 `IsEstimated` |
| `GameVramAssessor` | 按游戏判「充足 / 紧张」 | 需求 ÷ 本机显存 ≥ 85% 判紧张。**这是首页结论的来源** |
| `FrameTimeAnalyzer` | 帧时间统计 | 平均 FPS、1% Low、0.1% Low、尖峰（>100ms） |
| `DiagnosisEngine` | 卡顿归因 | 把尖峰与同刻指标对齐：显存压力 / CPU 瓶颈 / 单核打满 / 帧时间平稳 |
| `ChartGeometry` | 折线坐标计算 | 抽成纯函数才能单测；全平数据走中线避免除零 |

### Library

| 类 | 职责 |
|---|---|
| `GameLibrary` | 聚合各平台扫描器，按路径规范化去重 |
| `SteamLibraryScanner` | 解析 `libraryfolders.vdf` + `appmanifest_*.acf` |
| `WeGameLibraryScanner` | 解析 `rail_apps/名称(ID)`，挑主程序时优先 `-Win64-Shipping.exe` |
| `WeGameDisplayNames` | ID → 中文显示名映射（本地配置全加密，只能内置表） |
| `NonGameFilter` | 剔除 Wallpaper Engine、SteamVR 等非游戏 |
| `BackgroundProcessWhitelist` | 可结束进程预设（标准 / 强力）+ 硬编码保护兜底 |
| `EssentialProcessGuard` | 按客观特征判必要进程：Session 0 / 注册服务 / 系统目录 |
| `BackgroundWhitelistStore` | 用户勾选状态持久化到 JSON |
| `ProcessDisplayNames` | 进程名 → 中文应用名（白名单展示用） |

### GameMode

`GameModeController` 顺序执行动作，**任一失败立即回滚已执行的部分**，不留半套状态。

三个动作：

| 动作 | 改动 | 回滚 |
|---|---|---|
| `PowerPlanAction` | 切高性能电源计划 | 恢复原计划，并回读确认 |
| `EndProcessAction` | 结束白名单内正在运行的非必要进程 | 无法恢复，如实告知 |

`GpuPreferenceAction` 与 `GameDvrAction` 保留实现但**已从游戏模式移除**：
核显机器上没有可调度的独立 GPU，写显卡偏好不会生效，属于空转项。

**必要进程判定**（`EssentialProcessGuard`）按客观特征，不靠名字猜：
Session 0 = 服务会话、已注册服务的主程序、`%SystemRoot%` 下的 Windows 组件。
实测本机有 5 个进程以服务身份运行（wallpaperservice64、telemetry_agent 等），
硬编码名单既猜不全也说不清，所以必须按特征判定。

**核心设计**：`Apply()` 之后必须回读系统状态确认真的生效。`powercfg` 退出码为 0 也可能没生效，不回读就会向用户报虚假成功。

## 界面

左侧导航（首页 / 数据）+ 顶部常驻状态栏。用 `Visibility` 切换而不是 `TabControl`，因为顶部状态栏要两页共用。

`Sparkline` 是自绘 `Polyline`，不引第三方图表库——曲线只是等间隔时间序列，没必要为此加几 MB 依赖。
