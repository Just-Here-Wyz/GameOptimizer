# 架构与模块

## 分层

```
GameOptimizer.sln
├── src/GameOptimizer.Core        纯逻辑，无 UI 依赖，可单测
│   ├── Collection/               数据采集（PDH 计数器、内存、显卡显存容量、进程 CPU 占用）
│   ├── Analysis/                 占用率配色、仪表角度、显存判定、CPU 诊断规则与优化建议
│   ├── Navigation/               页面可见性状态机 PageRouter（v2.1.2）
│   ├── Peripherals/              外设识别（设备树、型号、电量、连接方式）
│   ├── Library/                  游戏库扫描与非游戏过滤、显示名映射
│   ├── Download/                 下载内核：分片、续传、校验、限速（v2.2.0）
│   ├── GameMode/                 游戏模式动作与回滚总控（含进程恢复、内存清理）
│   └── Models/                   共享数据模型 + 使用说明书文案（v2.2.1）
├── src/GameOptimizer.App         WPF 界面（+ WinForms 托盘图标）
│   ├── app.manifest              v2.0.0 起声明 requireAdministrator
│   ├── OffscreenRenderer.cs      离屏渲染成 PNG（仅调试用，`--render <目录>`）
│   ├── ViewModels/               MainViewModel（全部界面状态）、AppIconCache（应用图标）
│   └── Views/                    MainWindow、PercentGauge、BatteryRing、DownloadPage、BackgroundWhitelistWindow
├── tests/GameOptimizer.Tests     xUnit 用例（836 个）
└── tools/                        运维脚本（PresentMon 链路验证）
```

**关键约束**：Core 不引用任何 WPF 类型。所有能测的逻辑都在 Core 里。

**目录纪律**：Core 下的顶层目录就是上表这几层，新代码按职责归位，
不为一份文案或一个工具类另开目录（说明书因此放在 `Models/`）。

## 数据流

```
┌──────────────────┐  每秒一次
│  PdhSampler      │──────────────┐
│  (WDDM 计数器)   │              │
└──────────────────┘              ▼
                          ┌──────────────────┐
┌──────────────────┐      │  MainViewModel   │──▶ PercentGauge（四项占用仪表）
│PeripheralScanner │─────▶│                  │──▶ BatteryRing（外设电量环）
│ (设备树 + HID)   │      │                  │──▶ 白名单 / 游戏列表
└──────────────────┘      └──────────────────┘
        │                          │
        ▼                          ▼
 PeripheralAnalyzer         GameModeController
 （合并成一台台设备）        （电源计划 + 结束后台，可回滚）
```

## 各模块职责

### Collection

| 类 | 职责 | 关键点 |
|---|---|---|
| `PdhSampler` | 读 WDDM 性能计数器 | 主适配器按 `Total Committed` 最大值选，不能用 `FirstOrDefault`（会选到虚拟显示器） |
| `SystemPressureSampler` | 磁盘吞吐 + 总 CPU | **只做两项**，其余候选指标实测价值不足已筛除（见已知限制第十四节）；每项独立降级，某项缺失不影响另一项。**总 CPU 与磁盘吞吐各有一个单项读取方法**，因为同一秒读两次同一计数器会失真 |
| `ProcessCpuSampler` | 进程级 CPU 占用排名（v2.3.x） | `TotalProcessorTime` 差分 ÷ 墙钟 ÷ 逻辑核数，与任务管理器同语义；首帧无差分基准时返回 `IsReady=false`；受保护进程计入「读不到」不补 0 |
| `CpuIdentity` | 逻辑核编号与拓扑的对应（v2.3.x） | 逐核占用要按 `CoreIndex` 归组，不能按枚举顺序硬猜 |
| `SystemMemoryInfo` | 物理内存总量 / 可用量 | 用 P/Invoke `GlobalMemoryStatusEx`；标称容量向上取整（15.73GB → 16GB） |
| `GpuMemoryInfo` | 显卡显存容量 | DXGI `GetDesc1`。独显取专用显存，核显取专用 + 共享；排除软件适配器 |

### Analysis

| 类 | 职责 | 关键点 |
|---|---|---|
| `OccupancyPalette` | 占用率 → 颜色档位 | 0~30 绿 / 31~60 蓝 / 61~80 橙 / 81~100 红。**口径只此一处**，界面不写触发器 |
| `GaugeGeometry` | 仪表盘角度计算 | 纯函数才能单测；满圈强制 360°，否则浮点误差会留一条缝 |
| `CpuDetail` | CPU 高级详情数据（v2.1.0，v2.3.x 起为页内二级视图） | 按大小核分组、挑峰值、生成结论文案；**条形宽度用 GridLength 星号列**，绑 Width 会变成像素。总 CPU 可空：读不到显示「未知」 |
| `CpuLoadAnalyzer` | CPU 负载诊断规则（v2.3.x） | 持续判定必须连续 ≥10 秒、缺帧断链、间隔 >2.5 秒断链；不足 10 秒只说「采样中」。阈值常量只此一处 |
| `CpuTrendGeometry` | 趋势折线坐标换算（v2.3.x） | 纯函数：时间戳 + 百分比 → 画布点；缺帧不连成假线 |
| `CpuOptimizePlanner` | 快速优化建议生成（v2.3.x） | 只把「读得到路径、非系统、非游戏、非本程序」的进程列为候选；每条都带依据 / 影响 / 回滚方式；无安全动作就明说没有 |
| `CpuOptimizeVerification` | 优化前后对比文案（v2.3.x） | 同口径同窗口（各 5 秒）；有效帧不足 3 帧写「无法对比」，不拿旧数据充数 |
| `VramAssessor` | 会话实测显存是否达标 | **双指标**：显存预算占用率 + 系统内存余量 |
| `GameVramDemand` | 每款游戏的显存需求 | 1080p 四档画质的需求表；未收录按体积推断并标 `IsEstimated` |
| `GameVramAssessor` | 按游戏判「充足 / 紧张」 | 需求 ÷ **当前剩余显存**（容量 − 占用，每秒更新） ≥ 85% 判紧张。**这是首页结论的来源** |

### Peripherals

| 类 | 职责 | 关键点 |
|---|---|---|
| `PeripheralScanner` | 对外入口 | 任何异常都转成 `PeripheralScanResult.Error`，不抛给界面；扫描后接 `VxeBatterySource` 实时补 VXE/ATK 鼠标电量 |
| `DeviceTree` | SetupAPI + CM 属性 + `HidD_GetProductString` | `CM_Get_DevNode_Property` 要 **DEVINST** 不是实例 ID，必须先 `CM_Locate_DevNode` |
| `PeripheralAnalyzer` | 设备树 → 一台台设备 | 合并同一物理设备的多个接口、剔除触摸板与虚拟设备（含父设备是 `ROOT\` / `SWD\` / `LGHUBDevice\` 的软件枚举设备）、从容器借用蓝牙电量；键盘 + 鼠标并存时先看自报型号判主功能，判不出来就按接口各出一张卡（**没有「默认鼠标」兜底**） |
| `PeripheralClassifier` | 类别 / 连接 / 型号清洗 | 全部纯函数，用真机实例 ID 做回归用例。类型判定按「HID 用途页 + 用法」→「HID 系统集合 ID」→「设备类」→「描述文字（只降级为未知）」的可靠度排序，并返回人能复核的 `Basis` |
| `PeripheralDevice` | 对外的设备模型 | 读不到电量就是 `null`，界面显示「未知」，不编造数字；额外带 `Basis`（分类依据）与 `IsComposite` |
| `VxeBatterySource` | VXE/ATK（Compx）鼠标私有协议电量 | 分析厂商网页驱动（hub.atk.pro，WebHID）报文：FF02 集合 16 字节包，GetBatteryLevel=4，校验和；组包/解析是纯函数可单测 |

**为什么不用 `System.Management`**：那需要额外 NuGet 包，而 SetupAPI + CM 是系统自带，
且能拿到 HID 自报的型号（WMI 只能拿到驱动描述「USB 输入设备」）。

| `BackgroundProcessInspector` | 扫描结果 → 展示模型（应用名 / 发布者 / 用途 / 状态 / 识别依据），失败降级不抛异常 |
| `BackgroundProcessPurpose` | 用途识别：内置识别表、系统目录、注册服务、产品信息关键词；认不出写「用途未知」 |
| `ProcessFileMetadata` | 读 exe 版本资源（文件描述 / 产品名称 / 公司名 / 版本），按路径缓存，失败返回空对象 |
| `ProcessDisplayNames` | 进程名 → 中文应用名（白名单展示兜底用） |

### Download（v2.2.0）

下载内核。**不引用任何 WPF 类型**——这是唯一一条硬约束，理由与上文一致：
分片、续传、校验这些路径在真机上既难复现又极易写错，必须能用假 HTTP 层单测。

| 类 | 职责 |
|---|---|
| `DownloadService` | 调度（并发名额、队列泵）、探测、分片传输、收尾校验、速度采样、自动保存 |
| `IDownloadTransport` / `HttpDownloadTransport` | HTTP 通道（`GET` + `Range`）；测试换成 `FakeTransport` |
| `DownloadSegmentPlanner` | 纯函数：按 4KB 对齐切片，末片吃余数，小于 256KB 不分片 |
| `DownloadTask` / `DownloadSegment` | 任务与分片状态；**持久化文件是它唯一的跨进程真相** |
| `DownloadStore` | `downloads.json` 读写；先写 `.tmp` 再原子改名，断电不留半截 JSON |
| `Throttle` | 令牌桶，被所有任务共享，改设置立即生效 |
| `DownloadFileName` | 从 URL / `Content-Disposition` 取文件名并清洗非法字符 |

**断点以「每片已收字节 + 该片 SHA1」保存**：重启后只对**上次被硬中断**的任务自动续传
（`WasInterrupted`），用户主动暂停的保持暂停。

**校验失败先定位坏片**：逐片重算盘上 SHA1 与落盘时记下的片哈希比对，只重下对不上的片；
定位不到（坏字节是传输途中混进来的，片哈希算的正是这些坏字节）才整份重下。

### GameMode

`GameModeController` 顺序执行动作，**任一必需动作失败立即回滚已执行的部分**，不留半套状态。

| 动作 | 改动 | 回滚 |
|---|---|---|
| `PowerPlanAction` | 切高性能电源计划 | 恢复原计划，并回读确认 |
| `EndProcessAction` | 结束**未勾选保护**、且通过安全检查的正在运行进程（`protectedNames` 在执行侧再拦一次受保护项） | **按原路径重新拉起被结束的进程**；恢复失败如实上报 |
| `MemoryCleanAction`（v2.0.0） | 释放闲置工作集，**不结束进程** | **空操作**：页会随进程运行自然回到内存，无需还原 |

**核心设计**：`Apply()` 之后必须回读系统状态确认真的生效。
`powercfg` 退出码为 0 也可能没生效，不回读就会向用户报虚假成功。

#### 必需动作 vs 可选动作（v2.0.0）

`Add()` 注册必需动作，`AddOptional()` 注册可选动作：

| | 必需动作 | 可选动作 |
|---|---|---|
| 失败时 | 立即回滚全部并返回错误 | 不中断、不回滚 |
| 失败去哪 | 返回值（界面报「开启失败并已回滚」） | `Warnings`（界面照常展示，不静默） |

内存清理、以及 v2.1 计划中的网络参数 / CPU 亲和性都属于可选：
多一处平台差异就可能整轮失败，一项锦上添花不该挡住整个游戏模式。

`IGameModeAction` 接口自 v1.x **未做任何改动**，`AddOptional` 只是在总控侧多认一个集合。

#### 内存清理的实现分层

| 类 | 职责 |
|---|---|
| `MemoryCleanAction` | `IGameModeAction` 实现：枚举 → 跳过策略 → 逐进程释放 → 回读校验 → 汇报或抛错 |
| `IWorkingSetReleaser` / `Win32WorkingSetReleaser` | P/Invoke 通道（`SetProcessWorkingSetSizeEx` / `EmptyWorkingSet` / `GetAvailablePhysicalBytes`） |
| `MemoryCleanOptions` | 策略：最小工作集、前台进程保护、自身 PID、服务名集合 |
| `MemoryReleaseReport` / `MemoryReleaseEntry` | 结果模型：逐进程明细 + 两种口径的释放量 |
| `ElevationStatus` | 权限检测 + 失败原因 → 可行动文案 |

接口化的理由：「权限不足」「API 返回成功但回读没降」「回读时进程已退出」这三条路径
在真实机器上无法稳定复现，只能靠假实现测。v2.1 的优先级 / 亲和性动作可复用同一套
「枚举 + 逐进程操作 + 回读」骨架。

**展示口径的坑**（实测）：逐进程工作集减少量之和为 2.9 GB，系统可用内存只涨 461 MB，
差 6 倍——共享页面被重复计数。展示值以系统可用内存实测差为准，逐进程合计只用于明细。

## 界面

无边框窗口：`WindowStyle=None` + `WindowChrome`。**不用** `AllowsTransparency=True`，
后者会关闭硬件加速、让文字发虚。

```
MainWindow（自绘 1px 描边）
├── 标题栏 42px：应用名 + 三个窗口按钮（自绘 Path 图形）
├── 左侧窄导航 72px：总览 / 外设 / 下载 / 设置（唯一的页面切换入口，可见性由 PageRouter 决定）
└── 内容区
    ├── 总览页：UniformGrid 四个 PercentGauge + 内存「优化」按钮
    │            + 游戏模式（「管理后台进程」入口，浮窗见 BackgroundWhitelistWindow）+ 游戏列表（按实时剩余显存判定）
    ├── CPU 页：点击 CPU 仪表进入，与总览页共用区域（v2.1.0）
    │            页内二级导航（v2.3.x）：诊断（默认，含快速优化流程）/ 高级详情
    │            诊断：结论 + 当前占用 + 30 秒平均 + CpuTrendChart + 进程列表 + 完整性
    │            高级详情：汇总四项 + 核心 / 线程 + 拓扑 + 逐核条形图 + 系统压力
    ├── 外设页：WrapPanel 卡片，每张含 BatteryRing（不显示笔记本自带键盘）
    ├── 下载页（v2.2.0）：独立 `DownloadPage` 控件，新建栏 + 分组任务列表 + 全局统计栏
    └── 设置页：使用说明书（v2.2.1）、版本、采集状态、显存预算来源
```

**自绘控件**：

| 控件 | 用途 | 为什么自己画 |
|---|---|---|
| `PercentGauge` | 首页四项占用环 | 缺口造型 + 四档变色，没有现成控件；角度逻辑已单测 |
| `BatteryRing` | 外设电量环 | 同上，另需「有线 / 未知」两种降级显示 |
| `CpuTrendChart` | CPU 30 秒趋势折线 | 只有一条折线也要画坐标与降级文案；坐标换算在 Core 里，控件只负责绘制 |

**页面切换**用 `Visibility` 而不是 `TabControl`：标题栏与页内页头要长期可见，
`TabControl` 会把它们一起装进页签里。

**可见性只有一个写入方（v2.1.2）**：五个页面的 `Visibility` 全部绑定到
`Core/Navigation/PageRouter` 算出来的属性，代码后置**不出现任何 `Visibility` 写入**。
下载页沿用同一套（v2.2.0），只是页面本体拆成独立控件以免 `MainWindow.xaml` 继续膨胀。

v2.1.1 及以前总览页那组的可见性同时由「XAML 绑定」和「代码后置的 `ClearValue` / 赋值」管，
而 WPF 里绑定就是一个本地值：后置代码一赋值绑定就被顶掉，切回时 `ClearValue` 没有绑定可回落，
两个页面各自回落到默认的 `Visible` 叠成一片，「← 返回」也因为绑定失效而点了没反应。
现在导航只调 `MainViewModel.NavigateTo(index)`，`PageRouterTests` 用穷举断言
「任意操作序列下恰好一个页面可见」。

**托盘常驻（v1.0.2；关闭行为可选的第一版）**：`App` 里用 WinForms `NotifyIcon` 与 WPF 共存
（csproj 开 `UseWindowsForms`），`ShutdownMode = OnExplicitShutdown`。

窗口 `Closing` 一律先 `e.Cancel = true`，再按 `CloseBehaviorService.RequestClose()` 的结论分流：

| 结论 | 来源 | 动作 |
|---|---|---|
| `Ask` | 配置为「每次询问」（默认） | 弹窗；确认后由 `CompletePrompt` 给出真正的动作 |
| `HideToTray` | 用户选过并记住 / 本次选择 | `SetSamplingActive(false)` + 隐藏主窗口与浮窗 |
| `Exit` | 用户选过并记住 / 本次选择 / 托盘退出 | `ExitApplication` → `Shutdown()` |
| `Ignore` | 弹窗已经开着 | 什么都不做（不叠窗、不提前隐藏） |

**先 Cancel 再决定结局**是这条链路的关键：任何一条路都不会让窗口在用户确认之前消失，
退出也必然走 `OnExit → _vm.Shutdown()` 还原游戏模式。弹窗与设置页共用同一个 service 实例，
设置页改完立刻对下一次点 × 生效。

## 已移除的模块（v1.0.0）

「数据」页删除时一并移除了帧时间链路：

| 删除 | 原职责 |
|---|---|
| `FrameTimeSource` | 调 PresentMon 抓逐帧数据 |
| `FrameTimeAnalyzer` | 平均 FPS / 1% Low / 尖峰 |
| `DiagnosisEngine`、`DiagnosisFinding` | 尖峰 × 指标联动归因 |
| `ChartGeometry`、`Sparkline` | 曲线坐标与自绘折线 |

`SampleFrame.FrameTimeMs` 字段同时删除。遗留脚本 `tools/verify-frametime.ps1`
保留，用于独立验证 PresentMon 的 ETW 链路。
