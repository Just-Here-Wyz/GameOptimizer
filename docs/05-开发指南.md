# 开发指南

## 环境要求

| 项 | 版本 | 说明 |
|---|---|---|
| Windows | 10 / 11 | 全部 API 都是 Windows 专属 |
| .NET SDK | 8.0+ | 只需 SDK，运行时随 SDK 安装 |
| Git | 任意 | 换行符由 `.gitattributes` 统一 |

## 常用命令

```powershell
# 构建「用户真正双击的那个」Release 版（原地输出，快捷方式直接生效）
pwsh -File tools/build-app.ps1

# 构建完直接启动（会弹 UAC）
pwsh -File tools/build-app.ps1 -Run

# 仅调试用的 Debug 构建（不影响快捷方式指向的文件）
dotnet build
dotnet run --project src/GameOptimizer.App

# 测试
dotnet test

# 清理编译产物
dotnet clean
```

> **桌面快捷方式指向 `src/GameOptimizer.App/bin/Release/net8.0-windows/GameOptimizer.App.exe`。**
> 所以「改完给用户看」只有一条路：`-c Release` 原地编译。编 Debug、编到 `.artifacts`、
> 或者只提交代码，快捷方式指向的文件一点没变，界面上也就什么都没有——
> v2.5.1 当天正因为这个白折腾了两轮。`tools/build-app.ps1` 把这条固化成一条命令：
> 先检查有没有实例在跑（在跑会锁目录，MSB3027），再编译，最后回读产物的
> `FileVersion` 与 `Directory.Build.props` 比对。**别再用 `-p:OutputPath` 指定相对路径**：
> 它会按各项目目录解析，仓库根那份产物永远是旧的，照着验证会得出「改了没生效」的假结论。

> 推送 `main` 或打 `v*` tag 后，GitHub Actions 会用同一套命令在 `windows-latest` 上再跑一遍
> （配置见 `.github/workflows/ci.yml`）：`dotnet restore` → Release 构建 → `dotnet test`。
> 本地绿了 CI 基本不会挂；万一挂了，先看 run 里 `test-results` 附件的 trx 定位是哪一条，
> 不要靠重跑碰运气。

## 开发约定

### 0. 破坏性操作默认关闭

游戏模式结束后台属于**可逆操作**（v1.0.1 起关闭时按原路径恢复；v2.4.1 起改成由用户在弹窗里挑），
但白名单仍默认全不勾选，必须由用户主动选择；必要进程按客观特征自动排除。

这条来自实测教训：v0.5.1 收尾阶段曾因默认全选，
用户一点「开启游戏模式」就关掉了他正在用的壁纸引擎与任务栏美化。

### 1. 会改系统的操作必须能回滚

新增 `IGameModeAction` 时，`Apply()` 之后**必须回读确认真的生效**。

`powercfg /setactive` 退出码为 0 也可能没生效，不回读就会向用户报虚假成功——这个坑实际踩过。

### 2. 不可观测的东西不报结论

读不到外设电量就显示「未知」，不要用「上次充满」之类的推测填补空白。
没有数据时宁可显示「未知」，也不要给一个看起来很专业的假数字。

### 3. 失败必须可见

不要用 `catch { }` 吞掉异常。要么记录到状态栏，要么抛出。
`PowerPlanAction` 曾经吞掉所有异常，导致界面显示「已开启」而电源计划压根没变。

### 4. 单位换算写清楚

已经踩过的坑：
- `GPU Adapter Memory` 计数器返回**字节**
- `Memory\Available MBytes` 返回**MB**
两者混用会让显存显示成 1600 万 MB。

### 5. 路径比较先规范化

`d:/steam` 与 `D:\STEAM` 是同一目录。不规范化会导致同一游戏被扫描两次。
用 `GameLibrary.NormalizePath()`。

### 6. PowerShell 脚本必须带 BOM

```powershell
$text = [System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($true)))
```

Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 读，中文乱码后引发 `ParserError`。
`Ps1EncodingTests` 会强制检查这一点。

## 调试

### 采集不到数据

逐层排查：

```powershell
# 1. 计数器是否可读
Get-Counter '\GPU Adapter Memory(*)\Total Committed' -MaxSamples 1

# 2. PresentMon 是否能起来
powershell -ExecutionPolicy Bypass -File tools\verify-frametime.ps1

# 3. ETW 会话是否有残留
logman query -ets | findstr PresentMon
```

有残留会话时（管理员）：

```powershell
logman stop PresentMon -ets
```

### 游戏检测不到

```powershell
# 看游戏实际进程名
Get-Process | Where-Object { $_.MainWindowTitle } | Select-Object ProcessName, MainWindowTitle
```

若进程名与扫描到的 exe 主名差异很大，需要在 `GameProcessDetector` 里补规则。

### 页面可见性只能有一个写入方（v2.1.2 教训）

**永远不要在代码后置里写 `Visibility`**（`xxx.Visibility = ...` 或 `ClearValue(VisibilityProperty)`）。

WPF 里绑定就是一个本地值，赋值会把它**永久顶掉**；之后再 `ClearValue` 找不到绑定可回落，
属性回到默认的 `Visible`。v2.1.1 的「总览与 CPU 详情页叠在一起、返回按钮失灵」就是这么来的：

```
总览 → 外设：HomePage.Visibility = Collapsed   ← 绑定被顶掉
外设 → 总览：HomePage.ClearValue(...)          ← 没有绑定可回落，两个页面都变 Visible
```

页面切换一律走 `MainViewModel.NavigateTo(index)`，可见性由 `Core/Navigation/PageRouter` 算出来，
XAML 只做单向绑定。新增页面时记得在 `PageRouter` 里加属性，并在 `PageRouterTests` 的
穷举用例覆盖到——那条用例断言「任意操作序列下恰好一个页面可见」。

## 管理员权限

v2.0.0 起 `src/GameOptimizer.App/app.manifest` 声明 `requireAdministrator`，双击即弹 UAC。

| 功能 | 需要管理员 | 不提权会怎样 |
|---|---|---|
| 电源计划切换 | 是 | `powercfg` 静默不生效，回读校验能发现并抛错 |
| 内存清理（其他进程） | 是 | 只能清本账户未提权进程，其余记为「拒绝访问」 |
| 结束高权限后台 | 是 | `Kill` 抛 `UnauthorizedAccessException` |
| 采集 / 外设 / 游戏库 | 否 | 正常 |

**注意**：提权后进程处于 High 完整性级别，**Medium 完整性的自动化进程（如本仓库外部的
脚本、UIAutomation、`mouse_event`）无法向它发送输入**（UIPI 隔离）。
做 UI 自动化验证时，必须让辅助脚本同样以管理员身份运行，否则点击会静默无效。
