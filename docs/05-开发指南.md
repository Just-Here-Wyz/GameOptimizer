# 开发指南

## 环境要求

| 项 | 版本 | 说明 |
|---|---|---|
| Windows | 10 / 11 | 全部 API 都是 Windows 专属 |
| .NET SDK | 8.0+ | 只需 SDK，运行时随 SDK 安装 |
| Git | 任意 | 换行符由 `.gitattributes` 统一 |

## 常用命令

```powershell
# 构建
dotnet build

# 运行
dotnet run --project src/GameOptimizer.App

# 测试
dotnet test

# 清理编译产物
dotnet clean
```

## 目录速查

```
src/GameOptimizer.Core/Collection/   采集层，碰 Windows API 的地方都在这

src/GameOptimizer.Core/Library/      游戏库扫描

tests/GameOptimizer.Tests/           一个类一个文件，命名对齐被测类

```

## 开发约定

### 1. 会改系统的操作必须能回滚

新增 `IGameModeAction` 时，`Apply()` 之后**必须回读确认真的生效**。

`powercfg /setactive` 退出码为 0 也可能没生效，不回读就会向用户报虚假成功——这个坑实际踩过。

### 2. 不可观测的东西不报结论

没有帧时间数据时，不要输出「帧时间平稳」。宁可显示「采集未启动」。

### 3. 失败必须可见

不要用 `catch { }` 吞掉异常。要么记录到状态栏，要么抛出。
`PowerPlanAction` 曾经吞掉所有异常，导致界面显示「已开启」而电源计划压根没变。

### 4. 单位换算写清楚

已经踩过的坑：
- `GPU Adapter Memory` 计数器返回**字节**
- `Memory\Available MBytes` 返回**MB**
两者混用会让显存显示成 1600 万 MB。

### 5. 路径比较先规范化

`d:/steam` 与 `D:\STEAM` 是同一目录。不规范化会导致同一游戏被扫描两次。
用 `GameLibrary.NormalizePath()`。

### 6. PowerShell 脚本必须带 BOM

```powershell
$text = [System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($true)))
```

Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 读，中文乱码后引发 `ParserError`。
`Ps1EncodingTests` 会强制检查这一点。

## 调试

### 采集不到数据

逐层排查：

```powershell
# 1. 计数器是否可读
Get-Counter '\GPU Adapter Memory(*)\Total Committed' -MaxSamples 1

# 2. PresentMon 是否能起来
powershell -ExecutionPolicy Bypass -File tools\verify-frametime.ps1

# 3. ETW 会话是否有残留
logman query -ets | findstr PresentMon
```

有残留会话时（管理员）：

```powershell
logman stop PresentMon -ets
```

### 游戏检测不到

```powershell
# 看游戏实际进程名
Get-Process | Where-Object { $_.MainWindowTitle } | Select-Object ProcessName, MainWindowTitle
```

若进程名与扫描到的 exe 主名差异很大，需要在 `GameProcessDetector` 里补规则。
