## 未发布 — 游戏模式调强：结束后台

### 用户能看到什么

- 首页多了一块「开启游戏模式时结束后台」，列出**当前正在运行**的可结束应用
- 每项显示**中文应用名 + 进程名**（「壁纸引擎 Wallpaper Engine / wallpaper64」）
- 可逐项勾选、全选、全不选，勾选状态自动保存
- **不必要的自动不显示**：系统服务、Windows 组件、安全软件既不出现在列表里，也不会被结束
- 开启后明确报告「已结束 3 个进程，释放约 246 MB」

### 修了什么 bug，根因是什么

**现象**：点「开启游戏模式」后，界面上「已开启」，但实际什么都没发生。

**根因有三个**：

1. **白名单完全打不中**：旧名单只有 18 项浏览器/通讯软件，
   本机实测一个都没在跑。真正抢资源的是壁纸引擎（74MB）、华为电脑管家（32MB）、
   任务栏美化 TranslucentTB（140MB），一个都不在名单里。
2. **显卡偏好是空转**：`GpuPreferenceAction.TargetApp` 从未被赋值，
   `Apply()` 直接 return。而且本机是核显，写这个键本来也不会生效。
3. **结束失败被静默吞掉**：`catch { }` 吞掉所有异常，
   服务进程拒绝结束也不会体现在结果里。

**修法**：

- 白名单扩充并按实测补齐；支持用户自定义并持久化
- 移除显卡偏好与 Game DVR 动作，游戏模式只做「关闭后台」这一件事
- `EssentialProcessGuard`：按 Session 0 / 注册服务 / 系统目录判定必要进程，
  自动跳过且不展示，不再依赖猜名单
- `Kill` 之后回读 `HasExited` 确认，失败如实归入「拒绝访问」

### 实机验证

`平衡/高性能 → 开启 → 退出` 完整往返，电源计划确认还原；
实测结束 3 个进程释放 246MB，服务类进程被正确跳过。

### 测试

272 个用例（新增 `GameModeStrengthTests`、`EssentialProcessGuardTests`、
`BackgroundWhitelistStoreTests`、`ProcessDisplayNamesTests`）。

## 未发布 — 修复首页显存判定

### 用户能看到什么

- 首页每款游戏按**自己的显存需求**给出结论，不再全体共用同一个占用率
- 结论只有两种：**显存充足 / 显存紧张**，一眼能看懂
- 顶部显示本机的实际显存容量与来源（实测 / 估算）
- 悬停结论文本可看到「这款游戏约需多少 / 本机多少 / 占用百分比」

### 修了什么 bug，根因是什么

**现象**：首页所有游戏显示同一个结论，跟游戏本身没关系。
8GB 显卡上「无畏契约」和「三角洲行动」会同时「显存充足」或同时「不足」。

**根因有两个**：

1. **判定口径错**：`RefreshAllGameStatus()` 把同一份全局 `VramAssessor` 结果套给每一款游戏，
   游戏名、体积、需求全都没参与计算。
2. **显存预算算错**：预算固定取「物理内存的一半」。
   独显机器上 8GB 显卡 + 32GB 内存会被算成 16GB 预算，于是**任何游戏都显得充足**。

**修法**：

- 新增 `GameVramDemand`：1080p 四档画质的游戏需求表 + 未收录游戏按体积推断（标明估算）
- 新增 `GameVramAssessor`：按「这款游戏正常要多少 ÷ 本机显存」判定，≥85% 判「紧张」
- 新增 `GpuMemoryInfo`：DXGI `IDXGIAdapter1::GetDesc1` 读专用/共享显存。
  独显取专用显存，核显取专用 + 共享；读不到才退回估算并标记「未实测」
- 排除软件适配器（`Microsoft Basic Render Driver`），否则虚拟机里会读到 0MB

### 测试

215 个用例（新增 `GameVramAssessorTests`、`GameVramDemandTests`）。

## v0.5.0 — 首个可用版本（2026-10-19）

### 交付内容

**界面**
- 左侧导航（首页 / 数据），顶部设备状态栏两页常驻
- 内存显示为「已用 / 总量」，如 `10.4 / 16 GB`
- 数据页五条曲线：帧时间、显存、可用内存、GPU 3D、最高单核

**采集**
- WDDM 性能计数器：显存、内存、GPU 3D、逐核 CPU，每秒一次，无需特权
- PresentMon 帧时间采集：stdout 流式读取
- 物理内存总量：P/Invoke `GlobalMemoryStatusEx`

**游戏库**
- Steam：解析 `libraryfolders.vdf` + `appmanifest_*.acf`，多库目录
- WeGame：解析 `rail_apps/名称(ID)`，多盘库，中文显示名映射
- 非游戏过滤：Wallpaper Engine、SteamVR、Redistributable 等

**游戏模式**
- 高性能电源计划 / 显卡性能偏好 / 关闭后台进程
- 全部可回滚，回滚失败会明确上报

**诊断**
- 显存双指标判定（预算占用率 + 内存余量）
- 帧时间尖峰识别、1% Low / 0.1% Low
- 归因：显存压力 / CPU 瓶颈 / 单核打满 / 帧时间平稳

### 开发过程中修掉的真实缺陷

全部由实测发现，不是理论推演：

| # | 现象 | 根因 |
|---|---|---|
| 1 | 显存显示 1606 万 MB | GPU 计数器返回字节，内存计数器返回 MB，混用了 |
| 2 | 游戏模式显示已开启但电源计划没变 | `powercfg` 失败被 `catch {}` 吞掉，且未回读确认 |
| 3 | 切换成功却被判定失败并回滚 | 解析 `powercfg` 输出用固定偏移，中文系统下把整行当 GUID |
| 4 | 显存显示 12MB（真实 1553MB） | 主适配器用 `FirstOrDefault`，选中了虚拟显示器 |
| 5 | 曲线整片空白 | `Sparkline` 把颜色绑到了自己注册的 DependencyProperty，目标却是 `Polyline` |
| 6 | 同一游戏扫出两条 | 路径未规范化，`d:/steam` ≠ `D:\STEAM` |
| 7 | 游戏模式回滚失败仍提示「已还原」 | 回滚异常被吞；改为收集并上报每项失败 |
| 8 | 显示 GPU 3D 123% | PDH 在读数间隔异常时算出越界百分比，未钳制 |
| 9 | 采集失败却显示「正在采集」 | 只看 `Process.Start` 是否抛异常，没检查进程是否立刻退出 |
| 10 | 打开游戏仍提示「没有检测到游戏」 | 实际进程是 `-Win64-Shipping`，且反作弊阻止读 exe 路径 |
| 11 | 帧时间曲线永远为空 | PresentMon 的 CSV 独占打开，轮询读不到；改用 stdout |
| 12 | PowerShell 脚本报 `ParserError` | 无 BOM 的 UTF-8 被 5.1 按 GBK 读取，中文乱码 |
| 13 | 游戏列表显示 `DeltaForce` | WeGame 目录用英文工程名，本地配置全加密，只能内置映射表 |

### 测试

从 0 到 **184 个用例**。
