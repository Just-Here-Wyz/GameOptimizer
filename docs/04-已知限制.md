# 已知限制（v1.0.1）

这一节记录**明确做不到的事**。写出来是为了避免下一版误判现状，也避免把限制当成 bug 去修。

## 一、大多数无线键鼠的电量读不到

**现象**：外设页里接收器式无线鼠标显示「电量未知」。

**原因**：Windows 只为蓝牙外设提供统一的电量上报（`DEVPKEY_Bluetooth_Battery`，
对应 GUID `{2BD67D8B-8BEB-48D5-87E0-6CDA3428040A}` pid 4）。

罗技 HID++、VXE 私有命令、部分国产厂商的接收器协议都属于**私有协议**，
Windows 不解析。程序试过直接读 HID Feature Report，本机实测被驱动拒绝
（设备用 HidUsb 而非 WinUSB 打开，没有 CAPL 权限，`HidD_GetFeature` 直接返回失败）。

**因此**：

- 蓝牙耳机、蓝牙键鼠：能读到百分比 ✅
- USB 接收器式无线键鼠：读不到，显示「未知」⚠️
- 有线设备：不需要电量，显示「有线」✅

**不要**为了「有数字可显示」去编造电量或写入猜测值。

## 二、「有线 / 无线」在接收器场景是推断，不是读数

Windows 不区分「USB 有线」和「USB 接收器无线」。判定顺序：

1. 读到电量 → 无线（有电池才谈得上电量）
2. 设备名含 `Dongle` / `Receiver` / `接收器` / `Wireless` / `2.4G` → 无线
3. 蓝牙枚举（`BTHENUM` / `BTHLE`）→ 无线
4. USB / HID / ACPI / 板载音频 → 有线

**漏判场景**：一只接收器无线鼠标，产品名里既没有 Dongle 也没有 Wireless
（例如只报 `USB Optical Mouse`），且读不到电量 —— 会被显示成「有线」。
这是信息本身的缺失，不是判定逻辑的 bug。

## 三、耳机只从音频端点识别

HID 消费类集合（音量键、播放键）**不能**当作耳机：
键盘上的媒体键带同样的用途页 0x0C，实测会把罗技 G610 误判成一台耳机。

后果：没有音频端点的「耳机」（例如只用于手机、从未在 PC 上配对过的蓝牙耳机）
不会出现在外设页；纯 USB DAC 但名称不含「耳机 / Headphone」的端点同样不会。

## 四、外设页不区分「当前插着」和「曾经配对过」

扫描基于设备树的**当前存在**设备。耳机拔出后端点会消失，下次刷新就不显示。
未做「历史设备记忆」——那需要额外的持久化与过期策略，本版不做。

## 四·一、进程恢复的前提（v1.0.1）

关闭游戏模式时，只有**结束前能读到可执行文件路径**的进程才会被自动恢复；
读不到路径的进程（反作弊保护、权限不足）不自动恢复，界面如实说明。
恢复是「重新拉起同名程序」，不恢复窗口位置、未保存内容等运行时状态。

## 五、游戏显存需求表是估值

「显存充足 / 紧张」按每款游戏自己的正常需求判定，需求来自内置需求表（`GameVramDemand`）。

- **已收录的游戏**：表里给了 1080p 四档画质的量级，取偏保守的上沿
- **未收录的游戏**：按安装体积推断，界面会标注「估算值」，不要当成实测

需求表只收录经过确认的条目。**猜出来的数字比不显示更糟**。

判定固定使用「1080p 高画质」这个正常配置，不随用户实际画质变化。
若用户在游戏内开了 4K 极致，实际需求会高于界面显示值。

底线：`TightRatio = 0.85`，即需求超过本机显存的 85% 判「紧张」，留 15% 给桌面与系统。

## 六、帧时间采集与卡顿归因已移除

v1.0.0 按用户要求把「数据」页删掉，改为「外设」页。随之移除：

- `FrameTimeSource`（PresentMon 调用）
- `FrameTimeAnalyzer`、`DiagnosisEngine`、`DiagnosisFinding`
- `ChartGeometry`、`Sparkline`（自绘曲线）
- `SampleFrame.FrameTimeMs` 字段

外部脚本 `tools/verify-frametime.ps1` 保留，用于单独验证 PresentMon 的 ETW 链路，
不再被程序调用。

**这意味着工具不再回答「卡顿到底来自哪里」**，只回答「现在占用多少、外设还剩多少电」。
加回去需要重新引入上述模块，并处理 ETW 权限问题（见下一节）。

## 七、PresentMon 的 ETW 权限问题（保留备查）

若要恢复帧时间采集：

- 启动 ETW 追踪会话需要管理员，或账号属于 `Performance Log Users` 组
- 组权限配好也可能因为父进程是低完整性而失败（实测 `0xC0000022`）
- `--output_file` 写出的 CSV 在采集期间**独占打开**，外部读不到，必须用 `--output_stdout`

## 八、平台支持有限

只支持 Steam 与 WeGame。Epic、Xbox、Ubisoft Connect、独立安装的游戏都不会出现在列表里。

## 九、反作弊游戏的进程路径读不到

三角洲行动的 ACE、无畏契约的 Vanguard 会阻止跨进程读取 `MainModule` / WMI `ExecutablePath`。

**已应对**：`GameProcessDetector` 有「进程名前缀匹配」退化路径，不依赖读路径。
**遗留**：若游戏进程名与扫描到的 exe 主名毫无相似性，仍会漏检。

## 十、界面层的技术债

- `MainViewModel` 里直接用 `System.Windows` 类型的地方已清理（改为纯数据 + XAML 触发器）
- 没有历史数据持久化，关掉程序数据就没了
- 无边框窗口在**非 DPI 缩放 100%** 的屏幕上圆角与描边会有轻微模糊（`WindowChrome` 的固有行为）
