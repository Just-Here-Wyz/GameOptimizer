## 一、这是什么

Windows 桌面应用「游戏优化助手」：把**显存水位、内存、GPU 利用率、CPU 总占用与分核峰值、外设电量**摆到同一屏，并提供一个**全部可回滚**的「游戏模式」。

已发布版本 **v2.3.0**；此后并入的 CPU 诊断页与 CPU 快速优化尚未发版（见[变更记录](06-变更记录.md)「未发布」一节）。
形态是单文件 exe（自包含 .NET 运行时），系统托盘常驻。

### 它明确不做什么（读这条比读功能清单更重要）

| 不做 | 原因 |
|---|---|
| 温度监控 | ACPI 只能给不随负载变化的环境温度，真实核心温度要内核驱动 |
| 游戏内悬浮窗 / 帧率 | 需注入 DLL 或 PresentMon 定向监控 → 反作弊敏感，做了会给用户带来封号风险 |
| 一键提速的承诺 | 只报可验证的事实，不喊口号 |
| 静默安装 / 加驱 / 改系统服务 | 只改可回滚的用户态设置 |
| 编造数字 | 读不到就写「未知」或「未校验」，不用推测填空 |

**一句话原则：工具最容易骗人的地方不是算错，而是「看起来算对了」。**

| 层 | 选型 | 备注 |
|---|---|---|

| 权限 | `app.manifest` 声明 `requireAdministrator` | 另有运行时自我提权兜底 |
| 单实例 | 命名互斥体 + 广播窗口消息 | `Local\` 会话级 |
| 测试 | **xUnit 2.5.3 + FluentAssertions 6.12.2** | 709 例，只引用 Core |
| 发布 | `dotnet publish -r win-x64 --self-contained`（单文件） | 产物在 `publish/win-x64/`，附 `SHA256SUMS.txt` 与 `RELEASE_NOTES.md` |

## 五、七个必须理解的机制

### 1. 游戏模式 = 动作序列 + 回滚

`GameModeController` 顺序执行 `IGameModeAction`，**任一必需动作失败立即回滚已执行部分**，不留半套状态。

| 动作 | 做什么 | 怎么回滚 |
|---|---|---|
| `PowerPlanAction` | 切高性能电源计划 | 恢复原计划 + **回读确认** |
| `EndProcessAction` | 结束白名单内非必要进程 | **按原路径重新拉起**；恢复失败逐条上报 |
| `MemoryCleanAction`（可选） | 释放闲置工作集，**不结束进程** | **空操作**，页会随进程运行自然回来 |

**必需 vs 可选**：`Add()` 注册必需动作（失败即整体回滚），`AddOptional()` 注册可选动作（失败不拦路，但必须进 `Warnings` 上报界面）。

**铁律：`Apply()` 之后必须回读确认真的生效。** `powercfg` 退出码 0 也可能没生效——这个坑实际踩过。

### 2. 内存清理的展示口径（别把数字改大）

逐进程工作集减少量之和 **2.9 GB**，系统可用内存实际只涨 **461 MB**，差 6 倍——共享页被重复计数。

`MemoryReleaseReport.ReportedReleasedBytes` 因此**优先用系统可用内存实测差**，逐进程合计只用于明细。

想「看起来效果更明显」而去改成逐进程口径，等于虚假宣传，**明确禁止**。

### 3. 启动顺序：提权 → 单实例（不能反）

```
OnStartup
 ├─ 参数含 --render → 离屏渲染后退出（不抢锁、不提权）
 ├─ TrySelfElevate()  → 未提权就 runas 重启自己（带 --elevated-relaunch 哨兵防死循环）
 ├─ SingleInstanceGate.Acquire() → 已有实例则广播唤醒消息并退出
 └─ 正常启动：还原残留快照 → 建采样器 → 建窗口 → 建托盘
```

反过来的话，当前进程握着锁去拉起新进程，新进程会误判自己是「第二个实例」而退出。
`dotnet App.dll` 调试时 `ProcessPath` 是 dotnet.exe，**必须跳过自提权**（`CanSelfRelaunch`）。

### 4. 页面可见性只有一个写入方

`PageRouter` 算出五个页面的 `Visibility`，XAML 只做单向绑定。

**永远不要在代码后置里写 `Visibility`**——WPF 里绑定就是一个本地值，赋值会把它永久顶掉，再 `ClearValue` 也没有绑定可回落，两个页面会一起变可见（v2.1.2 的真实事故）。

新增页面：改 `PageRouter` + 绑 XAML + 在 `PageRouterTests` 的穷举用例里覆盖。

### 5. 采集随可见性启停

`MainViewModel.SetSamplingActive(bool)`：托盘隐藏、最小化 → 停；恢复 → 启动并立刻补一帧。

采样器每秒要为**每个逻辑核 + 每个 GPU 3D 引擎实例**各读一次 PDH（24 核机器 24 次起步）。
托盘常驻一整天还在每秒读，就是纯浪费——这个 bug 在 v2.3.0 才修掉。

### 6. CPU 数据的三条口径（别混着用）

| 指标 | 口径 | 用在哪 |
|---|---|---|
| CPU 总占用 | PDH `\Processor(_Total)\% Processor Time` | 首页仪表、诊断页当前值、30 秒平均、优化前后对比 |
| P 核峰值 | 全部逻辑核里**性能核**的最高值 | 高级详情，回答「跑游戏的那颗核忙不忙」 |
| 进程占用 | `TotalProcessorTime` 差分 ÷ 墙钟 ÷ 逻辑核数 | 诊断页进程列表、优化候选（与任务管理器同语义） |

两个硬要求：

- **同一秒只读一次总 CPU 计数器**：`NextValue()` 给的是「距上次读取」区间的平均值，同秒再读一次算的是极短区间，数字会失真。所以磁盘吞吐与总 CPU 拆成两个单项读取方法，按可见性决定读谁。
- **读不到就是 null**：`null` 表示没采到，界面写「未知」/「—」；0 表示采到了且空闲。把前者写成后者，用户会以为 CPU 很闲。缺帧同样不参与平均、不补零、并打断「连续 10 秒」的链路。

### 7. 白名单候选的判据

`BackgroundCandidateScan.ShouldOffer` 是**纯函数**（可单测），五道闸门依次放行：

1. 不在保护名单（系统外壳 / 杀软 / 输入法 / 本程序）
2. 会话 ID == 当前会话（排除 Session 0 服务、其他登录用户）
3. 不是已注册服务、exe 不在 `%SystemRoot%`
4. 不是游戏进程（按 exe 主名前缀匹配）
5. **读得到 exe 路径**（读不到就关了就拉不回来）

通过后再判：有顶层窗口 → 收；没窗口但属内置名单 → 也收（壁纸服务、同步盘）。

**注意「收」=「默认会结束」**：候选一旦进列表，只要用户没勾保护就会被结束（仍须过完上述安全检查）。
界面每行直接标「会结束 / 不会结束」，底部还会把名单写出来，不存在「点了才知道关了谁」。
勾选「保护」是无条件排除，优先于其他一切判断（见下方 `BackgroundKillPlan`）。

## 七、写代码前必读的硬约定

> 这些不是风格偏好，每一条都对应一次真实事故。

| # | 约定 | 事故来源 |
|---|---|---|
| 1 | **失败必须可见**：不许 `catch { }` 吞掉；改系统的操作要回读校验 | `PowerPlanAction` 吞异常 → 界面「已开启」但电源没变 |
| 2 | **不可观测的不报结论**：读不到就「未知」 | 外设电量 |
| 3 | **口径要有测试锁死**：多少算紧张、什么颜色算红，全落在独立纯类里 | `OccupancyPalette` / `GameVramAssessor` |
| 4 | **不注入、不加驱、不改系统服务** | 悬浮窗因此撤回 |
| 5 | **破坏性操作默认关闭**：白名单默认全不勾 | v0.5.1 默认全选，用户一点就关了壁纸引擎 |
| 6 | **不要 `FirstOrDefault()` 凑合**：硬件枚举 / 多实例必须遍历全部候选 | 两次同名 bug：VXE 电量、多耳机显示 |
| 7 | **单位写清楚**：GPU 计数器是**字节**，`Memory\Available MBytes` 是 **MB** | 显存显示成 1606 万 MB |
| 8 | **路径先规范化再比较**：`d:/steam` == `D:\STEAM` | 同一游戏被扫出两条 |
| 9 | **Core 不引用 WPF**：能测的逻辑必须放 Core | `ProjectLayoutTests` 会拦 |
| 10 | **PowerShell 脚本必须带 UTF-8 BOM** | 5.1 按 GBK 读 → ParserError |
| 11 | **每次改动都要有对应测试**，并 `dotnet test` 全绿后再交付 | `AGENTS.md` |
| 12 | **每次改动都要 commit**，中文信息，前缀 `fix:` / `feat:` / `docs:` / `refactor:` | `AGENTS.md` + `docs/03` |
| 13 | **同一个 PDH 计数器一秒只读一次**：`NextValue()` 算的是「距上次读取」的区间平均 | 总 CPU 与磁盘吞吐同秒各读一次时，第二个数字明显偏低 |

## 八、常见改动怎么做

### 新增一个「会改系统」的动作

1. 在 `Core/GameMode/` 实现 `IGameModeAction`（`Apply` / `Revert` / `IsActive`）
2. `Apply()` 里先记原状态 → 改 → **回读确认**，不生效就抛
3. 在 `App.xaml.cs` 的 `BuildGameMode()` 里 `Add()`（必需）或 `AddOptional()`（锦上添花）
4. 崩溃兜底快照若需要记它，改 `GameModeController.BuildSnapshot()` + `GameModeStateStore`
5. 补测试：正常 / 回读失败 / 回滚失败三条路径

### 新增一个页面

1. `Core/Navigation/PageRouter.cs` 加枚举与可见性属性
2. `MainWindow.xaml` 加容器 + 在 `NavList` 加导航项（顺序必须与 `PageRouter.ToNavIndex` 一致）
3. `PageRouterTests` 的穷举用例要覆盖新页面
4. **不要**在代码后置写 `Visibility`

### 改判定口径（显存 / 配色 / 强度）

先改 `Core/Analysis` 或 `Core/Library` 里的纯函数，再改它的测试。
**口径与实现分离**是故意的：改实现不能顺手改口径。

### 新增采集指标

1. `PdhSampler.Initialize()` 里建计数器，`Sample()` 里读
2. 单位换算在采样层完成（界面不换算）
3. 越界值必须钳制（PDH 实测给过 123%）
4. 只在真正可见的页面采（参考 `IsCpuDetailVisible` 的用法）

## 九、已知的坑（踩过的）

| 现象 | 根因 |
|---|---|
| 显存显示 1606 万 MB | GPU 计数器返回字节，内存计数器返回 MB，混用了 |
| 显示 GPU 3D 123% | PDH 在读数间隔异常时算出越界百分比，没钳制 |
| 游戏模式「已开启」但电源没变 | `powercfg` 失败被 `catch {}` 吞掉，且没回读 |
| 切换成功却被判定失败并回滚 | 解析 `powercfg` 输出用固定偏移，中文系统下把整行当 GUID |
| 总览与外设页叠在一起、返回失灵 | 页面可见性有两个真源（XAML 绑定 + 后置赋值） |
| 蓝牙耳机连上后有线耳机消失 | `FirstOrDefault()` 只取第一个音频端点 |
| 同一游戏扫出两条 | 路径未规范化 |
| 打开游戏却提示「没检测到游戏」 | 实际进程是 `-Win64-Shipping`，且反作弊阻止读 exe 路径 |
| 提权后 UI 自动化点不动 | UIPI 隔离：Medium 完整性进程无法向 High 完整性窗口发输入，辅助脚本也必须提权 |
| 构建报 MSB3027 / MSB3021 | `bin/Debug` 被正在运行的实例锁住，先结束进程 |
| CPU 仪表显示 25%，实际已经满载 | 旧口径取 P 核峰值，后台任务挤满小核时看不出来（v2.3.x 改为整机总占用） |
| 同一秒两次读数，第二个偏低 | PDH `NextValue()` 是区间平均，间隔越短越失真（见硬约定 13） |
| 刚进 CPU 页，进程列表是空的 | 进程占用要两次采样才有差分基准；首帧显示「采样中」，下一帧自动补 |

dotnet build                      # 构建

**发布流程**（详见 `docs/03-版本规则.md`）：

1. 改代码 + 补测试，`dotnet test` 全绿
2. 改 `Directory.Build.props` 的 `<Version>` / `<AssemblyVersion>` / `<FileVersion>`

版本规则：**功能/外观更新 → 次版本 +1、修订归零；仅修 bug → 修订 +1**。版本号由用户设定，不自动递增。

## 十二、给接手者的一句话

这个项目的价值不在功能多少，而在**每一个数字都能被追溯**：口径有测试、失败会说话、改动能回滚。

新增功能时，先问三个问题：

1. 它**做不到**的时候，界面会说什么？（不能沉默，也不能假装成功）
2. 这个判断的**口径**写在哪、有没有测试钉住？
3. 它改了什么系统状态，**怎么回滚**、回滚失败怎么上报？

三个问题答不上来，就先别写代码。
